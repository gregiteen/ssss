# GitHub Issue Mapping

The user's current instruction and canonical project tracker determine active scope. GitHub issues provide linked collaboration records where that repository uses them; reconcile disagreement rather than silently replacing local evidence. Discover actual labels, milestones and templates before requiring a convention.

## Rules
1. Link a PR to its applicable tracker item and related issue when one exists; do not fabricate an issue identifier.
2. Use configured labels and release cadence. Missing optional templates are not a universal readiness failure.
3. Record every meaningful local or authorized external issue/PR action in the tracker's final append-only Action Log with timestamp, agent, result and evidence. Remote reads/writes require actual access and scope; local template checks cannot prove remote validation.
