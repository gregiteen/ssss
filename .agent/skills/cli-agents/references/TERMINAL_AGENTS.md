# Terminal agent catalog

Official documentation checked **2026-09-30**. Sources appear beside each entry. This extensible inventory describes documented products; it does not certify installation, authentication, registry integration, or successful execution on any machine. Refresh the relevant source before adapting a command to a different installed version.

## Evidence and routing

Keep six independent states: **documented** (dated official source), **binary discovered** (resolved executable identity), **version compatible** (local help supports intended flags), **authenticated** (approved account route, without exposing credentials), **registered** (adapter and configuration exist), and **execution verified** (bounded authorized task produced its expected observable result). A registry entry proves none of the other states. Store machine-specific evidence in the project audit rather than this shared catalog.

Choose the user's configured subscription route when supported and authorized. Subscription sign-in, vendor automation credentials, and model-provider API billing are different routes. Never silently replace one with another after a quota or authentication failure. No entry implies free or unlimited usage. Current entitlement, quotas, permissions, and availability must be checked for the selected account. Preserve configured model selection; these examples deliberately omit model identifiers.

Commands below illustrate invocation and output syntax. They are **not permission profiles** and must not be launched until scoped tools, filesystem/network boundaries, hooks/plugins, deadline, and cleanup are configured. Some products default to approving edits or commands. A read-only prompt alone cannot enforce a read-only boundary.

## Local runtimes and additional executables

Ollama is a local/model runtime rather than proof of a repository-editing agent. Its [official CLI reference](https://docs.ollama.com/cli) documents `ollama ls`, `ollama ps` and `ollama run`; select an installed model from configuration, never a fixed model name in this skill. Its integration launcher can reconfigure other clients and must not silently switch an existing subscription workflow to a local/provider route. Local execution needs no paid provider key, while cloud models/account routes have separate entitlement. Discovery also reports legacy or custom names such as `grok` and `antigravity`; verify their actual implementation, official documentation and billing before any execution. Add other terminal agents through `--binary NAME` discovery and a verified adapter contract.

## Result and lifecycle contract

Capture stdout, stderr, exit status, structured terminal events, start/end times, and timeout/cancellation separately. JSON syntax, exit zero, or an agent's success statement does not prove the requested operation occurred. Antigravity soft tool denial is one documented example. Treat denied tools, missing final events, truncation, authentication/quota errors, and unexpected mutations as incomplete or failed outcomes. A timeout requires bounded process-tree cleanup and an explicit incomplete result. Do not retry by widening permissions, changing billing route, or pinning a guessed model.

When deploying this skill, propagate and compare the complete package, including references, scripts, evals, and delegation contracts. Matching only `SKILL.md` does not establish package parity. Keep propagation evidence separate from actual agent execution evidence.
